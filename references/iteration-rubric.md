# Iteration Rubric

Use this rubric before final delivery and whenever diagnosing live store data.

## Quality Gate

Score each item from 0 to 2:

| Item | 0 | 1 | 2 |
|---|---|---|---|
| Platform fit | Unjustified | Some reasoning | Clear beginner-specific tradeoff |
| Compliance | Risky claims | Some red flags | Safe wording and category cautions |
| Product specificity | Generic | Has category only | Has search words, price band, criteria |
| Profit logic | Missing | Rough multiplier | Explicit cost, shipping, margin, buffer |
| SEO | Generic titles | Keyword present | User + scene + keyword + benefit |
| Content | Vague posting advice | Basic framework | Complete visual and copy structure |
| Customer service | Partial | Covers common issues | Full pre-sale to after-sale scripts |
| Daily execution | Too broad | Partly timed | Fits inside 60 minutes |

If any item scores 0, revise before responding. If total is below 13, revise once.

## Data Diagnosis

Use the first failing metric as the bottleneck:

| Symptom | Likely Problem | Action |
|---|---|---|
| Low exposure | Weak keyword/cover/category signal | Rewrite title, cover text, first image |
| Exposure high, click low | Cover promise not specific | Add scene, number, before/after |
| Click high, save low | Product value unclear | Add dimensions, comparison, use proof |
| Save high, order low | Price/trust/SKU issue | Add coupon, size guide, FAQ, reviews if legitimate |
| Orders high, refund high | Product quality or expectation mismatch | Tighten product standards, detail-page warnings |
| Many questions, few orders | Customer script or SKU confusion | Add decision guide and default recommendation |

## Iteration Cadence

Daily:

- Keep publishing notes.
- Check one bottleneck.
- Change only one major variable per product: cover, title, price, or SKU.

Weekly:

- Keep SKUs with inquiries, saves, add-carts, or orders.
- Replace SKUs with zero meaningful interaction after 7-10 notes.
- Expand winning product into bundle, color, size, or adjacent scene.

Monthly:

- Build one stable category shelf.
- Negotiate supplier price or shipping.
- Add a second platform only after one product line is proven.

## Automatic Correction Prompts

When improving a weak plan, use:

`把这份方案改成更适合零基础低预算个人卖家：删除高资质/高售后/重库存选品，补齐1688筛选标准、利润公式、图文脚本、客服话术和每天1小时动作。`

When diagnosing data, use:

`根据曝光、点击、收藏、加购、成交、退款，找出第一个瓶颈，只给我今天要改的3件事和可复制模板。`
